⚡ Shakespeare on Grass

Localized Vision-to-Commentary Pipeline

An Apple Silicon-optimized system. A VLM extracts raw visual facts, and a fine-tuned MLX SLM translates them into poetic commentary in the style of legendary commentator Peter Drury.

Try the Playground Detailed Evaluation Report
⚠️ System Compatibility Warning

This project runs exclusively on Apple Silicon (M-series) Mac devices using Apple's local MLX framework for neural model loading and inference. It is not compatible with Windows, Linux, or Intel-based Macs out-of-the-box. To automatically generate the dataset, train adapters, run evaluations, and execute the final vision-to-commentary pipeline, you can run the e2e script: ./run_all.sh.

[BLIP Factual Output]: "a soccer player kicking the ball into the net"
Technical Details: The vision analyzer loads Salesforce/blip-image-captioning-large locally. Utilizing PyTorch's MPS (Metal Performance Shaders) backend, it routes operations to the Apple Silicon GPU to accelerate Vision Transformer (ViT) patch embedding and cross-attention text decoding. It extracts a non-stylized, objective factual description (such as player positions and action cues) without injecting commentaries.

Technical Details: To prevent instruction drift and standardize prompt layout, the engine wraps the VLM output into ChatML tokens. The system instructions configure the target commentator "persona" and style boundaries, while the user role supplies the factual scene. This establishes strict context fences before raw text generation begins.

Technical Details: The base 4-bit weights of the SLM (Phi-3-Mini) remain completely frozen. Instead, low-rank adapter matrices (rank r=8 or 16) intercept self-attention projection layers (specifically query, key, and value vectors). The adapter outputs adjust attention coefficients, steering the generation path towards dramatic metaphors and poetic phrasing.

Technical Details: Local inference is executed via Apple's MLX library, utilizing unified memory to remove CPU-GPU transfer overhead. Sampling parameters are set to temperature 0.85 and top-p 0.9. The engine implements safety fallbacks supporting both modern sampler utilities and legacy argument mappings.
